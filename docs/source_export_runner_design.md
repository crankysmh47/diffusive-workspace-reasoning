## Strict export reader

New stdlib `dwr/experiments/source_reader.py`, `read_source_export(run_dir, *, expected_manifest_sha256, split) -> tuple[dict,...]`. `split` exactly source_train/source_validation, never source_test/target. Verify terminal bytes against expected SHA first, then RunRecord.verify_artifacts; require completed, source_examples.jsonl+summary.json exact declared artifacts, and initial config operation/version matches source export. Pin output hash/counts against summary and terminal. Terminal hash is caller-bound; internal manifest links are integrity checks, not signatures.

Stream strict JSON lines, validate exact schema fields and IDs/profile/fine/origin/types, unique example IDs and origin indices across complete export, split only source_train/validation. Route first; validate tasks/solutions only for requested split, while required public routing/count integrity covers both. Parse serialized strict task, check original model input SHA, pure primitive profile and content/lineage/structure IDs; solution exactly assignment object, verify_answer accepted and deterministic canonical task/solution serialization. Do not rerun oracle per optimization batch; export already independently proved uniqueness. No input skip/truncation/relabel. Compare total split counts to summary and terminal; return records for requested split only after all checks pass. This reader deliberately has no Torch import; a later training driver builds SourceExample and forbids source_validation updates. Verify exact bytes again before success if read/hashes could have changed. Return detached JSON records, metadata outside task prompt. No automatic model tokenization or actual corpus read during tests.
