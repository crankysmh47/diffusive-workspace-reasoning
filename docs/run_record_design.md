# Resolved run records and artifact identities

2026-10-15. Root design for the next G3 component. Implements the binding [protocol](research_protocol.md), without launching an experiment. Luna implements; root decides and independent review checks the result. Owner delegated routine designs and requests consolidated commits.

The next deliverable is a small standard-library run-record writer, used first by the retained source export and later by native evaluation/probes. It creates an initial resolved manifest before work, records outcomes without overwriting evidence, and binds artifacts to bytes. It is not a training configuration validator or authorization mechanism. Each scientific consumer must strictly parse its own complete config; a manifest alone never authorizes a null or unregistered run.

## Contract

New `dwr/experiments/records.py`, empty package initializer and `tests/test_experiment_records.py`. Reuse strict JSON, stable serialization and file hashing from task run support; do not change historical task code or guards. No Torch or new dependencies. UTF-8/LF, Windows-safe paths.

`RunRecord.create(output_dir, *, command, config_path, expected_config_sha256, identities, rng_streams, settings, budgets, confirmatory=False, source_root=None)` returns a handle. Create the requested directory exclusively; refuse any pre-existing directory, even empty. Restrict run directory basename to ASCII letters/digits/underscore/hyphen, 1..100 chars. Parent must exist; output must not be within `.git`. No overwrite or continuation of an existing run. No hidden output path substitution. Capture exact resolved absolute paths and command arguments (nonempty list of strings), UTC start, Python executable/version/platform and exact installed package name/version inventory through importlib.metadata (no imports of ML libraries, GPU probing or network).

Read config bytes, verify expected lowercase SHA256 before parsing, reject duplicate keys/nonfinite JSON and require an object. Preserve full resolved object and actual hash in initial manifest. The caller's separate scientific loader remains necessary; test unknown top-level API kwargs fail naturally, not that this opaque config payload is scientifically validated.

Capture Git HEAD and porcelain-z status using byte subprocess output with explicit check/timeouts. `source_root` defaults to package repository root and must resolve to Git top-level; reject different nested roots. Capture SHA256 of tracked and untracked **nonignored regular files** using Git's `ls-files -z --cached --others --exclude-standard`, plus the binary HEAD diff SHA and status bytes SHA. Track missing tracked files explicitly; reject symlinks/reparse-point files and paths escaping root. This includes untracked source bytes, unlike a bare dirty diff hash. Record commit, clean flag and file inventory. Confirmatory creation requires clean status and actual disk file bytes equal their `git show HEAD:path` bytes; do not normalize line endings. Dirty exploratory creation records full inventory. No private file contents or diffs are printed/stored, only names/hashes. Worktree is already authorized; capture does not commit or modify Git. Git failures fail closed.

`identities`: nonempty mapping of descriptive string keys to exact `{name, revision, sha256}` objects; name/revision nonempty strings, SHA lowercase64. Include data/model/tokenizer/prompt/verifier as applicable; absence of a model for CPU export is a named settings entry, not a fabricated model hash. No extra nested identity fields. `rng_streams`: nonempty mapping of stream names to distinct nonboolean integers in [0,2**63); deterministic nonrandom operations may declare a seed with explicit unused policy in settings. `settings`: nonempty JSON object, consumer-owned resolved precision/determinism/cache/access policies; null may represent genuinely unavailable measurements, not required scientific choices. `budgets`: exact positive nonboolean `wall_seconds` (finite number), `memory_mib` (integer), `attempts` (integer). The writer records budgets; the consumer/watchdog enforces them. `confirmatory` actual bool. Validate input trees before creating output; reject nonstring mapping keys/nonfinite/non-JSON objects. Deep copy metadata, so caller mutation never changes records.

Initial file `manifest.initial.json` is exclusive immutable creation and status `running`; `manifest.json` terminal does not exist yet. `append_event(kind,payload)` appends one stable-JSON line with UTC and consecutive sequence to `events.jsonl`; payload JSON object, kind nonempty string. No append after termination. Preserve failure logs; writer is single-owner/process, no concurrency support. It must refuse a pre-existing events file on fresh creation.

`finish(status, *, counts, artifacts, error=None)` status exactly `completed`, `failed` or `interrupted`. `counts` is mapping of named nonnegative nonboolean integers. `artifacts` is a list of unique **relative** paths to existing regular files under this output directory; reject absolute, traversal, symlink/reparse paths, duplicates and manifest/events reserved names. Hash each file and record size; fail on missing/changed identities without silently dropping entries. Error is null or nonempty string; noncompleted outcomes require an error, completed rejects error. No scientific PASS interpretation is assigned to completed. Write an exclusive terminal manifest including initial-manifest SHA, events SHA/count, UTC end, elapsed monotonic wall, counts, artifact hashes and error. Flush/fsync written evidence. A second finish fails; no terminal rewrite. Errors encountered before finish leave initial/events intact and must be surfaced, not converted to success. No context manager that swallows exceptions.

`verify_artifacts(run_dir)` rereads strict terminal metadata and checks initial/events/artifact hashes and byte sizes, rejects absent/mutated/extra declared paths and returns the validated terminal object. No regeneration, model operation or scientific reclassification. Unknown manifest schema fields/version/status and invalid hash/size/count types fail. Unlisted arbitrary files do not become certified artifacts. Record file edits are detected by initial/terminal links, but this is integrity checking against an unmodified terminal manifest, not cryptographic signing or archival backup.

## Verification and boundaries

Meaningful stdlib tests use temporary real Git repos (configure local fixture author, no network): exact initial-before-work/terminal-once, input config hash/strict JSON failures, source dirty/untracked mutation identity, confirmatory dirty and CRLF-vs-blob rejection, detached metadata copies, unknown API kwargs/types, unique directories, artifact traversal/duplicates/missing/tampered bytes, failure/interrupted preservation, event sequence/terminal immutability and verify roundtrip. Test no ML import dependency. Scope suite only; root later runs full separated suites.

No actual retained corpus, pretrained weights/tokenizer, GPU operations, task training, target access, environment installation or commit in this component. Future export/eval/resume consumers and the registered full GPU probe remain required.
