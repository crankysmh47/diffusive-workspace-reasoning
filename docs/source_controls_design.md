## Small training API

Create `dwr/training/controls.py`, imported explicitly so standard-library task tools remain dependency-optional. Provide a frozen `SourceControl` description and:

- `configure_source_control(host, *, steps: int) -> SourceControl`: actual `Qwen2WorkspaceLM` only; nonboolean steps in {0,1,4}, exchangeable/max_steps4 only. Reject a trainable original, pre-existing gradients, inconsistent modules or unsupported horizon before changing flags. Set only workspace/readers flags for this explicit policy. Record method, horizon, ordered active parameter names, and total/original/new/active/excluded-workspace element counts. K0 has no active updater; K1 and K4 have identical active sets.
- `validate_source_control(host, control) -> None`: verify host architecture, original frozen/eval/gradient-free, exact active flags/names/counts and excluded gradient absence. Reject a mismatched host/control rather than change it. The description is architecture/policy metadata, not a model identity or checkpoint pin.
- `source_control_step(host, batch, noise, *, control, optimizer, scheduler, gradient_clip_norm: float, diagnose: bool = False) -> dict`: `batch` is the existing collated source batch; `noise` is an explicit fresh workspace tensor from the caller. Enforce the exact optimizer parameter set with no duplicate, missing or excluded parameter; the optimizer may have named groups. Use existing native forward with `steps=control.steps`, answer-only shifted loss and prompt masking; check finite loss, finite/present gradients for every active parameter and absent excluded/original gradients before any optimizer mutation. Diagnose live state gradients Z0..ZK and each reader; do not detach recurrent computation. For K0 the caller's noise need not require grad; the primitive may make a local noise leaf requiring grad for diagnostics without mutating the caller's tensor. Perform finite active-gradient clipping, optimizer step then scheduler step. Return numeric loss/token count, pre-update LR(s), finite gradient norms, state norms, optional state/per-reader gradient diagnostics and policy counts. Reject nonfinite updated learned parameters. Never swallow shape/config errors or silently drop a parameter.

This is a training primitive, not a job launcher or run manifest. Caller owns durable boundaries, identities, RNG, budgets, mode preservation during evaluation and failure sealing. Existing overfit run/source remains unchanged; do not refactor its validated runner into a generic framework. No automatic creation of an optimizer or hyperparameter defaults in the step primitive. No wall-clock efficiency claim from tiny CPU tests.

Root clarification after builder check, before implementation: accept exactly `torch.optim.AdamW` and `torch.optim.lr_scheduler.LambdaLR`, with `scheduler.optimizer is optimizer`. Align groups with the existing checkpoint contract: exactly one nonempty named `readers` group and, for K1/K4 only, exactly one nonempty named `workspace` group; members must belong to that module and cover its active parameters exactly. Every step begins with all host parameter gradients `None`; reject stale/accumulated gradients before computation. After collecting the diagnostic scalars and completing optimizer then scheduler, call `optimizer.zero_grad(set_to_none=True)` and verify all gradients `None`, so an immediate boundary checkpoint is valid. Failed steps are terminal to the caller; this primitive does not repair/retry a partially mutated update. A thrown error can leave diagnostic gradients for the caller's failure record. These choices prevent accidental accumulation and incompatible checkpoint state; no scientific comparison or prior result changes.
