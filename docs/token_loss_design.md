# Source token batching and answer-only loss contract

2026-10-15. Root clarification of Task2 in the [native plan](superpowers/plans/2026-10-14-native-backbone.md), before implementation or task training. No corpus is accessed or changed. Luna implements; independent review and exact CPU evidence follow. This is a hot-path collator/loss, not a dataset-membership certificate or training launcher.

`SourceExample(example_id, split, task, solution)` is a frozen record. ID is lowercase SHA256 text; split exactly source_train/source_validation; task and solution are actual strict task-schema types. Constraint kinds must be one source primitive, never a held-out composition relabeled as source. Gold must pass the existing strict verifier. Reject duplicate IDs in a batch, wrong types/unknown fields, invalid gold or protected/development splits. The future corpus consumer separately proves membership, uniqueness and ledger identity; no oracle/canonicalizer reruns inside each batch.

`TokenizerIdentity(name, revision)` is a frozen pair of nonempty strings. Real tokenizer file hashes/revision matching are later run-consumer obligations; the CPU fixture's explicitly synthetic identity is not a pinned pretrained tokenizer claim. A tokenizer must expose integer eos_token_id/pad_token_id and `encode(text, add_special_tokens=False)` returning a nonempty integer-ID list. Caller provides the **model embedding vocabulary size**, not tokenizer.vocab_size (added special-token IDs may exceed that base-vocabulary count). Reject bool/negative/out-of-vocabulary IDs and interior EOS/pad in prompt or gold; pad may equal EOS.

`collate_source_examples(examples, tokenizer, *, tokenizer_identity, vocab_size, max_prompt_tokens, max_answer_tokens, max_total_tokens, device)` returns `TokenBatch`: example_ids/splits/identity plus prompt_ids,prompt_mask,decoder_ids,decoder_mask,labels. All counts positive nonboolean integers; device explicit with no fallback. Each prompt is exact `serialize_model_input(task)` plus newline. Each gold is canonical strict assignment JSON. Encode prompt/gold separately without special tokens; append **one** EOS to gold. max_answer_tokens includes that EOS. Reject any overlength sequence without truncation/skipping. Build masks from lengths, never token-value comparison, so a valid EOS is not mistaken for padding.

Right-pad prompt/decoder tensors independently, dtype torch.long; masks Boolean contiguous valid prefix. Decoder valid sequence is prompt+gold+EOS; labels=-100 on prompt/padding and actual IDs on gold/EOS. Preserve valid prompt-prefix equality. Input records/lists are never mutated; IDs/metadata/gold stay outside prompt tensors. The collator permits source_validation for scoring only; the eventual optimization driver must require source_train for every update.

`answer_only_loss(logits, labels)` returns `AnswerLoss(loss, supervised_tokens)`. Logits are finite B,L,V with L>=2,V>0 and supported float16/bfloat16/float32/float64; labels are same-device B,L torch.long, with entries=-100 or vocabulary IDs and column0=-100. Every row must contain at least one supervised shifted token. Shift **once**: logits[:,:-1] predict labels[:,1:]. Select supervised positions before CE conversion; use FP32 loss for float16/bfloat16/float32 logits, preserve FP64 for float64 fixtures. Divide summed CE by actual supervised token count; reject nonfinite loss. This declared accumulation policy is shared across all methods and included in the later memory probe. Selection avoids converting the entire long sequence/vocabulary logit tensor to FP32 solely for ignored prompt tokens; full native logits/backward memory still counts.

Meaningful RED/GREEN checks: exact independent framing/separate tokenizer calls; no gold/annotation in prompt; valid EOS supervision when pad=EOS; unequal prompt lengths/right padding; invalid/duplicate/protected/mislabeled-composition/overlength inputs; independent hand-calculated shifted CE/count including first answer and EOS; changes to ignored **prediction positions** leave loss unchanged while first-answer/EOS positions matter; gradients are zero at ignored prediction positions and finite at supervised ones. Do not mistakenly mask the final prompt logit that predicts the first answer. Test loss shape/dtype/ID/finite/empty-row failures, and real tiny Qwen2 K4 forward/backward using this collator/loss with original weights immutable.

No actual source/target records, pretrained tokenizer/weights, GPU operations or task-training run in this task. CPU tokenization uses a declared ASCII fixture and a correspondingly sized real tiny Qwen2 vocabulary; random native-model checks do not certify pretrained encoding/quality. All original negative study, precision and protected-access boundaries remain unchanged.
