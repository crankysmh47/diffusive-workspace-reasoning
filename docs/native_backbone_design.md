## Encoder and reader placement

The original model is always frozen and in eval mode; all trainable modules are newly inserted. Extract X as the raw output after nine completed original decoder layers, in a separate **prompt-only**, adapters-disabled, no-grad pass. Use a host-owned single capture hook on layer8, call the original `backbone.model` with use_cache=False/output_hidden_states=False/output_attentions=False, and remove the capture hook in `finally`. For any allowed prompt_layer1..depth, X is raw output of layer(prompt_layer-1), before final model normalization, including the depth endpoint. Original model computation may finish the remaining layers; count that actual cost. The native host accepts explicit prompt IDs/mask and decoder IDs/mask, validates their prompt-prefix agreement and rejects invalid/noncontiguous padding, shapes, devices, dtypes and empty/all-padding rows. Answer IDs never enter this encoder pass. Prompt tensors are constructed separately by the token collator; answer changes must leave X byte-identical in the controlled CPU test.

The candidate reader layout is after zero-based decoder layers8,17,26. Each layer has its own new SetCrossAttentionAdapter, with decoder width1536, latent width768,12 heads and gate0.1. All methods use exactly this layout. The prompt extraction and reader locations are one-third/two-thirds/late positions chosen before any model output. Tiny native tests declare corresponding smaller indices and dimensions; this is interface coverage, not a changed scientific backbone.

Use temporary per-call native layer forward hooks, closed over that call's Z, and remove them in `finally` even on failure. Every prompt/decoder call explicitly disables native hidden-state and attention recording, rather than inheriting config defaults. Pinned Qwen2 layer output is a Tensor. No persistent mutable workspace cache, tuple guessing or generic fallback. Reject reentrant/concurrent host execution and pre-existing foreign layer hooks; reject gradient-checkpointing and KV-cache inputs in this first implementation because recomputation/cache with temporary hooks needs its own tested contract. Full frozen decoder computation after insertions stays autograd-enabled. The unaugmented reference uses the original model without hooks, with the same prompt/tokenization/decoding policy.

Caching is **off** initially for prompt states and autoregressive KV. Evaluation recomputes each full prefix with use_cache=False; its actual cost must be measured and reported. No cache-benefit claim. A later cache implementation must pin its full identity and validate equality before activation.

Concrete module: `dwr/models/qwen2.py`, explicitly imported by native users rather than eagerly from `dwr.models` so torch-only components remain usable without Transformers. `Qwen2WorkspaceLM(backbone, workspace, *, prompt_layer, adapter_layers, reader_heads, gate_init=0.1)` registers the actual backbone/workspace and new reader ModuleDict. Caller initializes the readers in a separately isolated matched stream; consuming the IDX identity stream must not shift reader weights. Construction validates Qwen2ForCausalLM/config/layer widths, distinct sorted nonboolean adapter indices and prompt_layer1..depth. Generic/fallback backbones are rejected.

`encode_prompt(prompt_ids, prompt_mask)` returns original prompt-only X. `decode_with_workspace(decoder_ids, decoder_mask, Z)` supplies native logits using the temporary readers; this enables direct whole-final-vector invariance checks. `forward(prompt_ids, prompt_mask, decoder_ids, decoder_mask, *, noise, steps=4, return_states=False)` verifies prefix agreement, computes X then Z then logits, and returns a small typed output with logits/workspace/optional live states. No labels/answers are arguments to prompt encoding or workspace updates. All token tensors are torch.long, IDs in vocabulary, nonempty; masks are Boolean contiguous right padding, with matching device/batch and at least one valid token. No KV/cache/unknown keyword arguments. Evaluation is initially single-example with unpadded prefixes.

Precision is explicit at the host boundary. A provisional feasibility candidate is BF16 original backbone plus FP32 workspace/readers/optimizer states, with autocast disabled inside new modules. The host casts frozen X and decoder queries to the new-module dtype, and casts reader output back to original hidden dtype before the next frozen layer; casts preserve autograd. This is a declared common-method boundary, not silent promotion inside the strict core. Validate that all new parameters share one dtype/device, all original parameters another declared dtype on that same device; original parameters remain frozen. CPU native correctness tests instead use float64 for all modules, with dropout0 and declared tolerances. No mixed-precision configuration becomes a training setting before the bounded real-model probe passes.

2026-10-15 phase-policy clarification before any scientific run: new modules are trainable by default, but the host must permit deliberate freezing of all learned parameters for transfer evaluation and of the unused EX updater for the K0 noise-memory control. It must not require every new parameter's requires_grad=True at every call. The later trainer enforces/logs the method's exact active-parameter set; this host never silently changes those flags. Original parameters are always frozen. CPU regressions check frozen-evaluation agreement and K0 frozen-workspace/active-reader gradients. All native calls force return_dict=True as well as disabling recording/cache, so unrelated config defaults cannot change the pinned output API.

Pinned output-API clarification: the outer Transformers4.57.1 decorator consumes return_dict=True before the inner model call; the LM then accesses last_hidden_state, so config.return_dict=False still breaks the inner output type. The host's exclusive execution guard temporarily sets that shared config flag True and restores its exact prior value in finally. Successful and forced prompt/decoder failures must leave flags/hooks/forward methods unchanged. This narrowly handles the verified pinned API; no hidden model/precision substitution or persistent config change. [Token/loss details](token_loss_design.md) fix the next Task2 contract.

## Tokenization, loss and evaluation contract

Frame each prompt as the exact existing `serialize_model_input(task)` plus one newline; frame gold as canonical strict assignment JSON. Encode prompt and answer **separately**, add_special_tokens=False, then concatenate and append one EOS to the answer. Do not use a chat template or include gold/solver annotations in prompt text. The constant newline is a prospective common framing choice; structural prompt-byte bins still refer to the frozen task serialization, not exact full token lengths. Record the framing/tokenizer identity. No truncation or skipped overlength row is allowed.

Collator uses right padding for training, explicit Boolean attention masks, and labels=-100 on prompt/padding. Answer JSON and terminal EOS are supervised. Loss shifts once: logits at i predict labels at i+1; first answer is predicted from the final prompt position. Reject a batch with no supervised answer token, mismatched prompt prefix or invalid EOS/ID. Compute token-summed CE divided by actual supervised token count; expose counts for reporting. Use explicit device/dtype rather than an implicit CPU fallback. Mixed precision and length/batch caps are selected only in the separately registered feasibility step.

Greedy generation is initially single-example, one explicit noise draw, with fixed Z across all answer steps. EOS terminates; hitting the cap is recorded. Remove only a terminal EOS before decoding with skip_special_tokens=False and cleanup disabled. All other output tokens remain visible to the strict verifier; malformed/truncated outputs count as failures. No best-of-noise or verifier search. Protected source ID-test, development diagnostic and final outputs remain inaccessible until separately registered terminal evaluation.

## Required implementation evidence and later gates

Meaningful tiny-native tests must establish: prompt-only X unchanged under answer changes; disabled adapters cannot affect X; raw extraction matches the selected layer output including depth endpoint; causal earlier logits unchanged by future answer changes; prompt padding and batched/single valid-state/logit agreement; EX equivariance and whole-final-vector reader/logit invariance for EX/IDX; exact loss shifting/masking including EOS; native frozen weights unchanged after an actual optimizer step; finite nonzero gradients into every reader/workspace group through all K4 states; strict input/config failures and capture/reader hook cleanup after forced prompt-pass and decoder-pass exceptions. Freeze backbone bytes and compare them after the synthetic step. All tests use the actual native modules, no mock claiming model validation.

Then build the exact passing-corpus consumer, resolved run manifests, strict per-example evaluation, optimizer/scheduler/scaler/RNG/sampler resume and end-to-end timing/cost accounting. Consumers reconstruct only explicitly permitted accepted candidates from the hashed raw ledger; source/dev routing occurs before task/answer payload consumption, and protected rows never enter pilot exports. Verify model-input hashes and strict solutions independently; do not regenerate or alter the corpus.

Before GPU task training, register a bounded real-pretrained full forward/backward/optimizer feasibility probe with exact candidate revision, common layout, precision, maximum sequence/batch/K, explicit GPU-memory/wall caps, synthetic input/noise identities and zero automatic scientific retries. It must include prompt encoding and answer decoding. Log unavailable costs explicitly. A synthetic probe is integration evidence, not a trained task effect. Training pilots require their own complete non-null exploratory registration; confirmatory transfer additionally needs prospective precision and three or more seeds. The seven-example diagnostic cell remains a limitation, not permission to refill a split.
