# First full pretrained GPU feasibility probe

2026-10-15 prospective root design. This is the next hardware gate after independently reviewed native/run/export/evaluation/resume components and stable-byte full CPU checks. It is **not launched by this design**. A separately reviewed closed config/runner, clean source commit and verified pinned artifacts are mandatory. No task training, test/target access, population change or learned-effect claim. The [protocol](research_protocol.md), [native host](native_backbone_design.md) and [artifact preparation](pretrained_artifact_preparation.md) apply.

## Decision and maximum shape

Question: can this exact frozen pretrained Qwen2.5-1.5B plus full fixed-N workspace/readers perform finite forward, backward and AdamW update within the single16GiB device budget, without disconnecting recurrent gradients or changing precision?

One invocation, one worker, one synthetic example, zero automatic retries. Common candidate for every later core method: pinned model revision8faed761d45a263340a0528343f099c05c9a4323, prompt X after9 completed layers, readers after zero-based8/17/26, N64,d768,12 workspace heads and12 reader heads, EX K4, gate0.1. Original weights BF16/frozen/eval, all new workspace/readers FP32/trainable. Explicit casts as verified host, autocast disabled in new modules, no scaler, no quantization, no parameter/gradient offload, gradient checkpointing, prompt/KV cache or remote code. Do not detach/reduce gradients to fit. Reader/common parameter initialization and explicit noise streams remain separate and matched for later comparisons.

Prospective first-pilot caps: prompt1024, answer128 including EOS, total1152, batch1, maximum K4. These are selected before retained-source token-length audit and model outcomes; the actual synthetic tokenizer fixture fits318+34. The corpus must later pass these exact caps without skips/truncation; if not, declare a separate common-method design change and probe its new maximum before training. This replaces no frozen study or registered2048-token run: no earlier GPU shape was registered. No wider K or variable N in this first gate. Other methods use no larger shape/layout; IDX adds only its explicit N*d identity parameters, and later IDX feasibility/cost must still be measured rather than inferred identical.

Native pretrained attention is explicitly PyTorch SDPA (`attn_implementation='sdpa'`), not a flash-attn package. CPU native correctness fixtures used eager; add matched tiny CPU SDPA causal/padding/backward checks before probe integration so the selected dispatch is exercised. Record actual Torch SDPA backend enablement and profiler kernel/operator names if available; no claim all hardware kernels are identical/deterministic. Set TF32 off, float32 matmul precision highest, cuDNN benchmark off; deterministic_algorithms=False is explicit, not a bitwise-replay promise. No hidden switch to math/eager/dtype if dispatch fails. PyTorch's normal predeclared SDPA dispatcher remains enabled; log its policy rather than promising a particular backend. No new third-party kernel dependency.

## Inputs, steps and costs

Synthetic IDs generated by an explicit CPU generator from integer range[100,10000), checked against actual model vocabulary and special IDs. Prompt length1024, answer127 synthetic IDs plus the actual EOS151643. Decoder=prompt+answer+EOS, labels=-100 on prompt, actual answer/EOS thereafter; all masks valid. No gold task, corpus record or held-out answer is involved. Record exact tensor SHA256s/shapes/dtypes and seed derivation. Workspace noise sampled by its own explicit CUDA generator; initialize ordinary CPU and CUDA global RNG explicitly as separate named streams, without relying on one seed for all roles.

Load the verified local safetensors model only, `local_files_only=True`, `trust_remote_code=False`, no device map/automatic placement or `.bin` fallback. Check config, actual parameter dtype/count, original freeze/eval and added module group identities; move the exact original/new modules to cuda:0. Record all actual parameter/gradient/optimizer-state byte counts and device/dtype inventories, including IDX difference as a planned later measurement. For this diagnostic only, set sampled noise.requires_grad_(True) and retain Z0..Z4 gradients, recording retained-state/noise-gradient overhead; ordinary training does not need a gradient into sampled noise. Require a finite non-None gradient on every active tensor, nonzero gradient at workspace and each reader group, and finite nonzero retained-state gradients through Z0..Z4. Record per-tensor norms, including legitimate zero key-bias directions rather than requiring every parameter tensor to be nonzero; preserve original parameter bytes/hash before/after (hash tensors sequentially on CPU, outside timed device sections, without retaining a second full base). No base parameter can change.

Exactly one full optimizer step after forward/backward, using AdamW lr0.0001, betas(0.9,0.999), eps1e-8, weight_decay0.01, amsgrad=False, foreach=False, fused=False; named active groups workspace/readers, nonconstant LambdaLR1/(step+1). This optimizer choice matches the supported CPU resume path, not a tuned learning choice. Answer-only loss uses registered selected-token FP32 accumulation. Zero grads only after recording/checking them; retain recurrent states for gradient verification and release after measurement. No warmup or timed repetitions: first-step allocation/optimizer-state materialization is the intended conservative measurement, not a latency benchmark. Synchronize at each measured boundary. Record prompt encoding, workspace, full answer decoding/LM logits, loss, backward and optimizer costs, or null for any inseparable decomposition. Total full step includes all of them. Do not substitute block counts for FLOPs; profiler FLOPs are nullable with explicit scope/unsupported operators.

After step/zero_grad(None), exercise learned checkpoint save/load in the already constructed host and fresh AdamW/scheduler/sampler/noise objects, using exact identities and initialized CUDA RNG layout. Perturb only new state/RNG deliberately, restore and compare learned parameter/optimizer/scheduler/noise/global RNG/sampler state; do not allocate a second full base. Record CUDA/scaler(None) checks separately from CPU4-step resume evidence. No extra training update in this probe. Actual enabled-scaler replay remains outside policy because BF16 base/FP32 new modules use scaler=None.

## Caps and stop rule

Wall900s including load/identity/step/checkpoint/evidence, external watchdog905s; CPU resident memory12288MiB; device cuda:0 must be the recorded RTX5060Ti (record full available identity/driver), total memory at least16000MiB and initial free at least14500MiB. Never terminate unrelated GPU apps to meet this gate. Peak allocated and reserved each must stay<=14336MiB, measured with PyTorch peak counters/reset immediately before candidate allocation, and record process/device used/free from available NVIDIA metadata. GPU kernel calls occur only after the initial run manifest/access event and exact registration/artifact/source checks. No device fallback.

Stop and preserve on missing hardware/free-memory preflight, unsupported dtype/kernel, OOM, wall/CPU/GPU cap, nonfinite value, disconnected required gradient, incompatible resume or base mutation. Outcome names distinguish ENVIRONMENT_BLOCKED, FEASIBILITY_FAILED and PASS_FEASIBILITY; none is G3/G4/model-learning PASS. No automatic rerun, smaller N/K/batch/length, alternative attention/dtype/model or detach. Root chooses a separately recorded bounded diagnosis/change from failure evidence; a scientifically complete negative hardware result is retained. Do not register comparative training until feasibility and actual permitted-source/validation/evaluation gates pass.
